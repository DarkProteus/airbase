## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
В новом дизайне (design.md §5) у миссии есть цель с собственными условиями победы и поражения, а враги идут не по фиксированному пути к базе, а на цель — в том числе подвижную. Аэродром отделён от цели. Новые типы целей должны добавляться позже через данные.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Цель задаётся в MissionConfig: тип + параметры; условия победы и поражения определяются типом цели, без ветвлений по id миссии
- [x] #2 Тест defend: победа, если объект продержался N секунд; поражение при прочности объекта ≤ 0; враги, дошедшие до объекта, наносят ему урон
- [x] #3 Тест escort: колонна движется по маршруту из конфига; победа, когда колонна дошла до выхода; поражение, когда колонна уничтожена
- [x] #4 Тест: враги наводятся на текущую позицию цели и меняют курс при её движении (escort)
- [x] #5 В src/content по одной миссии на каждый тип цели, обе проходят createSim и headless-прогон до won или lost
- [x] #6 Тест: полный headless-прогон каждой миссии детерминирован по сиду
- [x] #7 Цель (объект, колонна, её прочность) и аэродром отображаются на карте из снапшота
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. types: ObjectiveConfig (defend {pos,hp,duration} | escort {route,speed,hp}) в MissionConfig.objective; spawns + WaveGroup.spawn; path становится опциональным (легаси-миссии без цели работают по-старому: путь + жизни).

3. engine: EnemyState.pos; с целью враги спавнятся в spawns и летят на текущую позицию цели, дошедшие наносят leakDamage по цели; приоритет стрельбы — ближе к цели.
4. content: миссии defend и escort; тесты headless-прогона и детерминизма.
5. render/HUD: объект/колонна с полосой прочности, аэродром, враги по pos; строка HUD с прочностью и прогрессом цели.
6. npm run check + браузер.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Решения: (1) цель опциональна — миссии без objective (proto, sortie) работают по-старому: путь + жизни базы; с целью path не используется, враги появляются в MissionConfig.spawns (WaveGroup.spawn — индекс точки). (2) EnemyState получил pos; рендер и стрельба читают его вместо pointAt(path, dist). (3) Дошедший до цели враг (OBJECTIVE_REACH = 0.3 клетки) наносит ей leakDamage и исчезает — то же событие leak. (4) Приоритет мишени enemyThreat: с целью — ближе к цели, без неё — дальше по пути. (5) До экрана выбора миссию можно открыть через ?mission=evac|convoy. Проверка в браузере: headless Chromium, обе миссии в реальном времени ~40 с — объект/колонна с полосой прочности, аэродром и точки входа видны, колонна движется, прочность падает (колонна 9/20 на 43% пути, объект 5/20). Баланс миссий не настраивался (TASK-15): без авиации обе проигрываются, это под тестом.
<!-- SECTION:NOTES:END -->
