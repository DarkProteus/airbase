# AIRBASE — Aviation Defense

Браузерная аркадная tower defense. Игрок командует авиабазой, открывает классы авиации, собирает необычные сочетания подразделений и превращает небольшую базу в оборонительную систему.

Не авиасимулятор. Реальные самолёты дают узнаваемый облик и характер, но механика свободно балансируется ради интересных решений. Реальные ТТХ и процедуры не воспроизводим.

## 1. Игровой цикл

Самолёты — не турели: авиагруппы взлетают с аэродрома, летят в зону патрулирования, работают там, пока хватает топлива и боекомплекта, и возвращаются на перезарядку.

1. **База** (между миссиями): покупка и улучшение авиагрупп за валюту, заработанную в миссиях.
2. **Выбор групп на вылет**: 3 слота из 4 групп — выбор состава под цель миссии.
3. **Бой**: игрок назначает группам зоны патрулирования и двигает их по ходу боя. Покупок внутри боя нет.
4. **Итог**: победа или поражение по цели миссии, награда.
5. Снова **База**.

Отличие от простого TD: игрок не расставляет башни, а распределяет ограниченное время групп в воздухе. Группа не стоит в точке — она то в зоне, то в пути, то на перезарядке; решает, кто, где и когда окажется над целью.

## 2. Юниты

Начинаем с малого числа действительно разных юнитов, а не с 30 самолётов, которые отличаются только уроном и ценой. Каждому юниту нужна уникальная механика. В первой версии около 6 юнитов, включая наземные системы поддержки.

Роли-примеры (не окончательный список):

| Юнит | Роль | Суть |
|---|---|---|
| F-16 | Универсал, базовый | Дёшев, гибок, стабильно справляется с обычными волнами. Улучшения дают выбор специализации. |
| EA-18G Growler | Синергия | Мало личного урона. Усиливает союзников или ломает способности противников. Один слаб, в группе силён. |
| E-3 Sentry | Глобальный эффект | Зона поддержки, улучшает осведомлённость союзников, помогает с особыми событиями. Сила зависит от построенной системы. |
| A-10 | Контроль волн | Силён против многочисленных обычных целей, слаб против единичных сильных. Требует прикрытия. |
| C-130 | Экономика | Ускоряет восстановление ресурсов или даёт бонус между волнами. Выбор: вложиться сейчас или в будущее. |

## 3. Три слоя стратегии

- **Авиация** — основная сила. Юниты отличаются доступностью, специализацией, стоимостью, поведением.
- **Инфраструктура** — усиление: ангары, абстрактное обнаружение, сервисные объекты. Конкурирует с покупкой авиации за бюджет.
- **Синергии** — мастерство игрока. Сочетания эффективнее суммы частей: один усиливает, другой продлевает эффект, третий получает способность от этой связки. Игрок должен иногда сам найти комбинацию, которую обучение не показывало.

Пример решения перед волной (500 кредитов): купить ещё истребитель, улучшить имеющийся юнит, вложиться в инфраструктуру, сохранить деньги перед сложным этапом. У каждого варианта должна быть понятная цена. Если один вариант всегда выгоднее, баланс сломан.

## 4. Баланс

| Правило | Смысл |
|---|---|
| Нет универсального лучшего юнита | Сильные стороны сопровождаются ограничениями |
| У каждого юнита есть назначение | Игрок понимает, зачем его покупать |
| Открытия меняют стратегии | Прогрессия не сводится к большим числам |
| Экономика ограничивает выбор | Нельзя сразу купить всё самое сильное |
| Старые юниты остаются полезными | Они дешевле решают конкретные задачи |

Грубый ориентир: эффективность = полезный эффект за матч / (стоимость покупки + содержание). Это не абсолютная формула (поддержка полезна без урона), но помогает находить явные перекосы.

Нужен внутренний headless-симулятор: автоматически гоняет сотни матчей с разными составами и случайными условиями, чтобы проверять баланс не только на ощущениях.

## 5. MVP: Prototype 0.1

Цель: одна полноценная короткая сессия «База → Бой → Итог → База», а не коллекция недоделанных механик.

**Бой**

- Аэродром — на краю карты, отдельно от цели миссии. Группы взлетают оттуда, поэтому время перелёта важно.
- Игрок ставит группе зону патрулирования (круг) и может двигать её в любой момент.
- Цикл вылета (в sim): взлёт → перелёт → патруль (таймер топлива, боекомплект) → возврат → перезарядка (время) → снова.
- Цели по тегам: истребители бьют `air`, штурмовики — `ground`.

**Цель миссии** задаётся в `MissionConfig` (тип + параметры); каждый тип — свои условия победы и поражения:

- `defend`: удержать объект N секунд (эвакуация); поражение при прочности объекта ≤ 0.
- `escort`: колонна идёт по маршруту, враги наводятся на неё; победа — колонна дошла до выхода, поражение — колонна уничтожена.

Новые типы целей — потом, через данные.

**Состав MVP** (4 группы, на вылет берутся 3):

| Группа | Роль | Суть |
|---|---|---|
| F-16 | Истребитель | Бьёт цели `air`. |
| A-10 | Штурмовик | Бьёт цели `ground`. |
| EA-18G Growler | РЭБ | Аура в зоне: враги медленнее, ударные (`strike`) группы сильнее. |
| C-130 | Экономика | Бонус к награде за каждый завершённый вылет. |

**Данные**: `AirGroupConfig` — роль, теги, скорость, топливо, боекомплект, время перезарядки, оружие с целевыми тегами, аура-модификаторы. Контент = данные, sim детерминирован. Аура-система должна позволять добавить ДРЛО (+радиус) и заправщик (+время патруля) одними данными.

**База**: покупка и улучшение групп, выбор трёх на вылет. Прогресс сохраняется между сессиями.

Чек-лист:

- [x] Цикл вылета в sim
- [x] Зоны патрулирования: назначение и перенос в бою
- [x] Цели миссии `defend` и `escort`, по одной миссии на каждый тип; враги наводятся на подвижную цель
- [x] Четыре группы на `AirGroupConfig`, таргетинг по тегам, баланс проверен headless-прогонами обеих миссий
- [x] Экран базы: покупка, улучшение, выбор 3 групп
- [x] Поток База → Бой → Итог → База
- [x] Сохранение прогресса
- [x] Модели, анимации, базовые звуки (допустимы примитивы)

Вне MVP: ДРЛО и заправщик, ручной перехват/удар, кампания с переносом потерь.

Критерий успеха: матч хочется переиграть. Если нет, механику нужно переделывать, а не наращивать контент.

## 5.1. Этап 0.2: понятно, красиво, есть во что играть

MVP собран и опубликован: https://darkproteus.github.io/airbase/. Ядро «зоны патрулирования + вылеты» остаётся без изменений. Этап закрывает четыре пробела; задачи — TASK-22…35 в Backlog.

| Блок | Что даёт | Задачи |
|---|---|---|
| A. Понятность боя | Здоровье врагов, типы целей, предупреждение о волне; разбор итога по группам и волнам; обучение первого вылета | 22–24 |
| B. Визуал | Составные низкополи-модели как данные (собраны из кода, без внешних файлов), модели групп и врагов, окружение карты, эффекты, оформление интерфейса и звук | 25–29 |
| C. Контент | ДРЛО и заправщик данными; враги с механикой (броня, малозаметность, носитель); 3–4 уровня улучшений с выбором специализации; шесть миссий | 30–33 |
| D. Прогрессия | Кампания с открытием миссий и звёздами, сохранение версии 2; экономика и баланс по headless-прогонам | 34–35 |

После блоков A+B, C и D — игра на опубликованной версии и правки по ощущениям.

Вне этапа: новые типы целей, ручные приказы в бою, потери и ремонт групп, дерево исследований, достижения, мобильное управление, внешние 3D-модели.

## 6. Технологии

- TypeScript + Vite — приложение и игровая логика
- Three.js — изометрическая 3D-сцена с фиксированной камерой
- React — интерфейс, меню, карточки юнитов
- Zustand — экономика и состояние матча
- Vitest — тесты игровой логики

Ключевой принцип: симуляция полностью отделена от визуализации (без импортов Three/React), чтобы менять баланс и гонять автоматические матчи без 3D-сцены.

## 7. После MVP (порядок)

1. Ещё несколько юнитов, каждый со своей механикой.
2. Постоянная коллекция техники и дерево исследований.
3. Карты и условия миссий, меняющие ценность составов.
4. Испытания, достижения, сохранение результатов.
5. Полноценный визуал, анимации, звук.

После каждого крупного этапа играть самому, искать имбовые комбинации и переделывать механику.
